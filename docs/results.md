# Measured application examples

[User manual](usage.md#command-line-experiments) · [Evolution theory](evolution.md)

These are recorded simulation results, generated by this repository's actual `updateSimulation()` and Evolution module, not invented sample numbers or measurements of a physical car. The runner excludes browser rendering, wall-clock scheduling, and saved storage. The [raw JSON records](examples/evolution-seed-42.json) include configuration and runtime metadata; a [second record](examples/evolution-seed-2026.json) uses seed `2026`.

## Reproduce the runs

Using the recorded implementation with Node.js `v24.18.1`:

```bash
node scripts/run-experiment.cjs --seed 42 --generations 3
node scripts/run-experiment.cjs --seed 2026 --generations 3
```

Both runs use 100 controllers, mutation amount `0.1`, at most 600 steps per generation, and no saved network. The model has one traffic vehicle. Distances are canvas units rounded to six decimal places; car numbers below are one-based. A future algorithm or random-consumption change can produce different values. Another engine may have floating-point differences.

## Example A: improvement with seed 42

| Generation | Steps | Winner | Peak forward distance | Winner survived |
| --- | --- | --- | --- | --- |
| 1 | 600 | Car 67 | 1215.600000 | Yes |
| 2 | 600 | Car 84 | 1278.457206 | Yes |
| 3 | 600 | Car 14 | 1295.878502 | Yes |

This run's best completed controller comes from generation 3. Its peak displacement improved across these three evaluations. This is an observation about one seed and scenario; it does not establish generalization or a universal improvement rate.

## Example B: plateau with seed 2026

| Generation | Steps | Winner | Peak forward distance | Winner survived |
| --- | --- | --- | --- | --- |
| 1 | 600 | Car 37 | 1305.950000 | Yes |
| 2 | 600 | Car 1 | 1305.950000 | Yes |
| 3 | 600 | Car 1 | 1305.950000 | Yes |

The archive retains generation 1's champion because later results tie its distance and survival. Car 1 in later generations is the unchanged elite. Mutation did not improve the measured objective in these three generations, illustrating stagnation rather than a failure of the generation loop.

Both runs complete 1800 updates, representing 30 simulated seconds. The command normally finishes faster than a 30-second browser run because it performs no rendering and does not wait for real-time callbacks. Its execution duration is not a browser performance benchmark.

## Observe the same setup in the browser

Pause, set the chosen seed, disable Use saved network, enable Evolution mode, and Restart. Resume or use Step to finish generations. Last completed and Best completed progress correspond to completed evaluations, rounded to two decimal places in the UI.

At the 600th update, generation 1 is complete; the 601st update starts generation 2 and performs its first step. To inspect an exact boundary, remain paused and use Step, or use the command-line results instead of trying to pause at a particular wall-clock instant. More than one fixed update may occur in a rendering callback.

Saving a champion changes the input to a future run if saved loading is enabled. Keep it disabled when comparing these seed-only examples.
